# 答题中断恢复 + 临时保存 + 继续测试 功能可行性计划

## 一、现状问题确认

| # | 问题 | 根因 |
|---|------|------|
| 1 | 答题异常中断后回来，已答内容全部清空 | 三个答题页（[test_paper_detail.html](file:///d:/0_TG/code2026/need_to_do/quiz/templates/quiz/frontend/test_paper_detail.html)、[do_class_assignment.html](file:///d:/0_TG/code2026/need_to_do/quiz/templates/quiz/frontend/do_class_assignment.html)、wrong_question_paper.html）均为"一次性表单提交"，答案只在最终 POST 时落库（`create_test_and_answer_records`），中间无任何持久化 |
| 2 | 限时考试中断后更严重 | 倒计时基于 `session['exam_start_{id}']`（[views_paper.py](file:///d:/0_TG/code2026/need_to_do/quiz/views_paper.py#L119-L133)），session 过期/丢失后回到页面直接 `exam_block` 阻断，连已答内容也看不到；班级考试超时自动提交得 0 分（不统计已答答案） |
| 3 | 无临时保存功能 | 全项目无草稿概念 |
| 4 | 离开答题页无提示 | 答题页无 `beforeunload` 拦截 / 返回提示 |

## 二、总体方案

引入统一的**答题草稿（TestDraft）**机制，覆盖三个答题入口（公开试卷、错题组卷、班级作业/考试）：

1. **答题过程持续落库**：手动"💾 临时保存"按钮 + 每 30 秒自动保存（有改动时）+ 离开页面时尽力保存，答案写入数据库草稿表。
2. **草稿进入"答题历史记录"页**：展示"进行中"卡片，提供 **继续测试** / **放弃草稿** 操作；班级作业同时在学生作业列表标注"继续答题"。
3. **离开答题页提示保存**：`beforeunload` 原生提示 + 页内链接（返回/导航）拦截弹窗（保存并离开 / 直接离开 / 取消）。
4. **限时考试计时改为数据库连续计算**：以草稿 `start_time` 为准，关闭浏览器再回来剩余时间继续倒数；到期自动用已保存答案提交（不丢分）。

## 三、详细设计

### 3.1 数据模型（新增迁移 0033）

```python
class TestDraft(models.Model):
    user = models.ForeignKey(User, on_delete=models.CASCADE, verbose_name='用户', related_name='test_drafts')
    test_paper = models.ForeignKey(TestPaper, on_delete=models.CASCADE, verbose_name='试卷', null=True, blank=True)  # 公开试卷/错题组卷
    assignment = models.ForeignKey(ClassAssignment, on_delete=models.CASCADE, verbose_name='班级作业', null=True, blank=True)  # 班级作业/考试
    is_wrong_paper = models.BooleanField(default=False, verbose_name='是否错题组卷')
    answers = models.JSONField(default=dict, verbose_name='答题内容')  # {"question_id": "答案串"}
    current_index = models.IntegerField(default=0, verbose_name='逐题答题位置')
    mode = models.CharField(max_length=10, default='full', verbose_name='答题模式')  # full/single
    start_time = models.DateTimeField(null=True, blank=True, verbose_name='开始时间')  # 限时考试计时起点
    updated_at = models.DateTimeField(auto_now=True, verbose_name='最后保存时间')
    created_at = models.DateTimeField(auto_now_add=True, verbose_name='创建时间')

    class Meta:
        verbose_name = '答题草稿'
        verbose_name_plural = '答题草稿'
        ordering = ['-updated_at']
        constraints = [
            models.UniqueConstraint(fields=['user', 'test_paper', 'is_wrong_paper'],
                                    condition=models.Q(test_paper__isnull=False), name='uniq_draft_test_paper'),
            models.UniqueConstraint(fields=['user', 'assignment'],
                                    condition=models.Q(assignment__isnull=False), name='uniq_draft_assignment'),
        ]
```

- 草稿**惰性创建**：首次 `save_draft` 时 `get_or_create`，浏览试卷不答题不产生草稿（避免历史页噪声）。
- 答案格式与后端 `collect_user_answers` 一致：单选/判断 = `"A"/"对"`，多选 = 排序拼接 `"AB"`。

### 3.2 后端视图（views_paper.py / views_class.py）

| 视图 | 改动 |
|------|------|
| `test_paper_detail` (GET) | 认证用户有草稿 → 注入 `draft_answers`（json_script 预填）+ 计时改从 `draft.start_time` 计算；到期且草稿有答案 → 自动提交草稿（计分）→ 跳结果页（对齐班级考试超时自动提交语义）；匿名用户保持 session 计时不变 |
| `submit_test_paper` (POST) | 超时校验改读 `draft.start_time`（无草稿时回退 session）；创建 TestRecord 成功后删除草稿 |
| `save_draft` (新, AJAX POST) | 入参：`paper_id`、`answers_json`、`current_index`、`mode`、`source=paper/wrong`；校验访问权限（公开 or 本人 or is_staff；wrong 必须 `created_by=本人`）；`get_or_create` 草稿并保存；新建且限时 → `start_time = session开始时间 or now`；返回 `{success, answered_count}` |
| `discard_draft` (新, POST) | 删除本人草稿（`draft/<id>/discard/`） |
| `test_history` (GET) | 追加查询本人草稿（select_related paper/assignment），模板展示"进行中"卡片：已答 X/Y 题、最后保存时间、剩余时间（限时显示/超时标记） |
| `submit_wrong_question_paper` (GET/POST) | GET 预填草稿；POST 成功删草稿 |
| `do_class_assignment` (GET) | 有草稿 → 预填；计时维持 `ClassAssignmentRecord.start_time`（不重构班级考试计时源）；考试超时且草稿有答案 → 用草稿答案计分而非固定 0 分 |
| `submit_class_assignment` (POST) | 成功提交后删除对应草稿 |
| `save_assignment_draft` (新, AJAX POST) | 同 `save_draft`，按 `assignment_id` 关联 |
| `student_class_assignments` (GET) | 每项附加 `has_draft`，模板显示"继续答题"徽标 |
| `reset_exam_status` (管理重置) | 重置时同步删除该作业下学生草稿 |

### 3.3 前端模板

**新增共享片段 `quiz/frontend/_draft_save_script.html`**（三页复用，避免重复代码），通过模板变量注入保存 URL：

1. **答案预填**：`{{ draft_answers|json_script:"draftAnswers" }}`，JS 在 DOMContentLoaded 恢复 radio/checkbox 选中态与 `.selected` 高亮。
2. **临时保存按钮 + 状态条**：`💾 临时保存`（点击立即保存并提示"已保存 HH:MM:SS"）；有改动未保存时显示"有未保存的更改"。
3. **脏标记**：选项点击/输入变化 → `dirty=true`。
4. **自动保存**：`setInterval` 30s，`dirty` 时触发 `saveDraft()`。
5. **序列化**：按 `collect_user_answers` 同规则把表单转 `{qid: answer}`，`fetch POST + FormData(含 csrf)`。
6. **离开拦截**：
   - `beforeunload`：`dirty` 时 `navigator.sendBeacon` 尽力保存 + 触发原生离开确认；
   - 页内 `<a>` 链接委托拦截：`dirty` 且目标离开当前页 → 自定义三选弹窗（保存并离开 / 直接离开 / 取消）。
7. **倒计时到期**：沿用现有自动 `form.requestSubmit()`（服务端按草稿计时判定）。

**改动页面**：
- `test_paper_detail.html`：加入上片段 + 保存按钮/状态条样式。
- `wrong_question_paper.html`：同上（`save_draft` + source=wrong）。
- `do_class_assignment.html`：同上（`save_assignment_draft`）。
- `test_history.html`：顶部新增"⏸ 进行中（临时保存）"卡片区（继续测试 / 放弃草稿）。
- `student_class_assignments.html`：有草稿的作业卡加"继续答题"徽标。

### 3.4 边界行为

- **限时公开试卷到期恢复**：详情页自动用草稿提交（计分）→ 结果页，杜绝"回来即清空/阻断"。
- **max_attempts**：草稿不占用次数，提交才算一次（沿用 TestRecord 计数）。
- **作业截止**：`do_class_assignment` POST 已有截止校验，草稿"继续测试"受同一约束。
- **草稿引用已删除题目**：恢复时过滤（答案键不在当前题集则忽略）。
- **草稿空答案**：惰性创建保证只在有作答时生成；放弃草稿即时删除。
- **班级考试计时源不变**：仍为 `ClassAssignmentRecord.start_time`，草稿只存答案，降低对既有 P2-3 考试逻辑的回归风险。

## 五、测试验证方案

- 静态检查：`manage.py check`、`makemigrations --check --dry-run`、`migrate`。
- 功能回归（test client + 关键场景 browser_use 真实浏览器）：
  1. 公开试卷：作答 → 临时保存 → 历史页出现草稿 → 继续测试 → 答案预填 → 提交 → 草稿消失、TestRecord 生成。
  2. 中断模拟：保存后直接再进详情页 → 答案回填。
  3. 限时考试：作答保存 → 重进剩余时间连续递减 → 过期 → 自动按草稿提交计分。
  4. 班级作业：保存草稿 → 作业列表"继续答题" → 恢复 → 提交 → 草稿清理。
  5. 班级考试：保存草稿 → 超时自动提交按草稿计分（而非 0 分）。
  6. 错题组卷：保存/恢复/提交。
  7. 离开提示：点返回/导航链接弹保存确认；直接关闭/刷新触发 beforeunload。
  8. 权限：他人草稿不可见/不可删；未登录访问 save_draft 被拒。
- 回归既有 P2 要点：倒计时自动交卷、max_attempts 限制、时间窗口阻断、班级考试单次提交、`json_script` 序列化规范（视图传 Python 对象，禁止预 json.dumps）。

## 六、风险与注意事项

- **限时公开试卷 GET 自动提交**存在 GET 副作用，但与班级考试既有"超时自动提交"语义一致，且草稿提交后即删除，无重复提交路径。
- 班级考试超时由"0 分"改为"按草稿计分"，属行为增强，需用户确认；无草稿时仍为 0 分。
- 模板改动遵循项目约束：新片段标签单行、<80 字符；涉及关键模板用 .NET WriteAllText 规避 IDE 格式化（如需要）。
- 不修改 routes 之外已有 URL 语义；全部为新增 URL + 视图内增强。
- 草稿表数据增长可控（每用户每试卷最多 1 条），无需清理任务。
