## Current State Analysis（现状分析）

### A. 模板层跨行 bug（2 处，高危）

Django 模板引擎对 `{{ }}` 标签跨行不解析，会泄露为字面文本。

1. **`quiz/templates/quiz/admin/import_questions.html:504-505`**
   - 现状：`questionsData = {{ questions_json | safe }` + 换行 + `    };`
   - 影响：`{{ questions_json | safe }}` 被拆跨行无法解析，JS `questionsData` 赋值失败（try/catch 兜底为空数组），导入试题预览/校验流程的 `getQuestionDataFromDOM`（L511-559）拿不到数据
   - 修复目标：改为单行 `questionsData = {{ questions_json | safe }};`

2. **`quiz/templates/quiz/frontend/class_detail.html:202-204`**
   - 现状：`...font-size:14px">{{` + 换行 + `        pending_count }} 个</span>...`
   - 影响：待审核申请数显示成字面文本 `{{ pending_count }}` 而非数字
   - 修复目标：把 `{{ pending_count }}` 放同一行（span 标签内联）

### B. Python 层高危逻辑错误（聚焦关键）

1. **`quiz/models.py:143-155` TestPaper 双重计算总分**
   - `save()` L146 在已存在实例时 `sum(question.score for question in self.questions.all())` 重算 total_score
   - `m2m_changed` 信号 L154 又算一次并 `instance.save()`，触发 save() 再算一次
   - 结果：每次 add/remove 题目触发 2 次 total_score 计算 + 2 次 DB 写入；改 title 等无关字段也重算
   - 修复：`save()` 跳过 total_score 重算（除非显式更新题目）；`m2m_changed` 用 `update()` 而非 `save()` 断开递归链

2. **`quiz/views.py:43-155` process_confirm_import 无事务**
   - 循环内大量 `get_or_create`（Subject/Chapter/Section/KnowledgePoint）+ `Question.objects.create` + `knowledge_points.set`，整个导入在 `try/except Exception` 外无 `transaction.atomic`
   - 中途失败：已创建的 TestPaper/Question/学科结构残留为脏数据
   - 修复：用 `@transaction.atomic` 包裹 process_confirm_import 主体

3. **`quiz/views.py:386-389` profile 统计竞态条件**
   - `profile.total_score += score; profile.tests_taken += 1; profile.save()` 读-改-写模式，并发提交丢失更新
   - 修复：用 `F()` 表达式 `Profile.objects.filter(pk=profile.pk).update(total_score=F('total_score')+score, tests_taken=F('tests_taken')+1)`

4. **`quiz/middleware.py:55-68` 频率限制失效**
   - `cache.set(key, requests + 1, window)` 每次都重置 TTL，持续请求会无限续期，限流永不过期
   - `cache.get` 与 `cache.set` 非原子，并发可突破上限
   - 修复：首次用 `cache.add(key, 0, window)` 设置 TTL，后续用 `cache.incr(key)`（不重置 TTL）；提示文案"30秒"与实际 window（60s/300s）不符，改为动态

5. **`quiz/middleware.py:108-118` cookie 校验过弱**
   - `has_valid_cookie` 仅检查 `len(cookie_value) == 32`，攻击者伪造任意 32 字符串即可通过
   - 修复：用 HMAC 签名（`hashlib.md5(secret + ua + ip)`），服务端 `secrets.compare_digest` 校验

### C. 严重 N+1 查询与性能（聚焦关键）

1. **`quiz/views.py:411-418` test_history 循环 count + 访问外键**
   - `for record in paginated_records: record.question_count = record.test_paper.questions.count()`
   - 每条记录 1 次外键查询 + 1 次 count 查询（N+1）
   - 修复：`TestRecord.objects.filter(user=...).select_related('test_paper').annotate(question_count=Count('test_paper__questions'))`

2. **`quiz/views.py:644-650` user_center 5 次独立 count**
   - `TestRecord.filter().count()` × 2、`WrongQuestion.filter().count()` × 1、`AnswerRecord.filter().count()` × 2
   - 修复：合并为 1-2 次聚合 `aggregate(Count(...))`

3. **`quiz/views.py:813-817` my_test_papers 循环 count**
   - 修复：`TestPaper.objects.filter(...).annotate(question_count=Count('questions'))`

4. **`quiz/views.py:359-369` submit_test_paper 循环 AnswerRecord.objects.create**
   - 每题一次 INSERT，题目多则慢
   - 修复：构建 `AnswerRecord` 对象列表后 `bulk_create`（注意错题收集逻辑仍用循环，因为依赖 result['question']）

5. **`quiz/views.py:701-707` + `847-853` 循环 Question.objects.get**
   - `create_wrong_question_paper` 和 `create_test_paper` 逐题 `Question.objects.get(id=q_id)`
   - 修复：`Question.objects.filter(id__in=question_ids)` 一次查，再循环 add（保留 score 累加）

6. **`quiz/utils.py:62-63` calculate_score 两次 dict get**
   - `user_answers.get(str(question.id), user_answers.get(question.id))` 每次 2 次查找
   - 修复：先 `key = question.id; ans = user_answers.get(key) or user_answers.get(str(key))`
