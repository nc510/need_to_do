## 二、总体方案

### 2.1 三类发放模式（核心设计）

给 `StarItem` 增加 `effect_type`，按效果类型决定**发放模式**，存量道具自动落到「人工核销」，完全向后兼容：

| 模式 | 适用道具 | 行为 |
|------|----------|------|
| **A 即时生效型** | 会员卡 ×4、正确率重置卡、斩题卡 | 兑换**当次事务内**直接生效，兑换记录自动置为「已发放」 |
| **B 背包使用型** | 改名卡、错题组卷卡、答案提示卡、头像框 | 兑换后自动入背包（记录置为「已发放」），到具体场景「使用」时消耗 1 张 |
| **C 人工核销型** | 现有实物/无 `effect_type` 的道具 | 维持现状（待发放 → 后台核销），作为兜底 |

即时生效型的「生效」与「扣币」在同一事务内 → 效果失败则整体回滚，星币自动退回，不会出现「扣了币没生效」。

### 2.2 背包口径（派生，不新增库存表）

```
可用数量 = Σ(已发放兑换的 quantity - used_quantity)
```

- 不给 `StarRedemption` 之外再建库存表，避免「库存表 vs 兑换记录」双写不一致。
- `used_quantity` 记录该条兑换已用掉几张，避免为一张卡建一条流水。
- 新增 `StarItemUsage` 使用流水（谁 / 何时 / 用了哪个道具的哪张卡 / 上下文），供后台审计。

### 5.4 破晓·辉月（答案提示卡）— B 背包使用型 ✅ 已决策：覆盖三类答题页

- **入口**（3 个答题页，每题右上角加「💡 提示」按钮）：
  1. 公开试卷 [test_paper_detail.html](file:///d:/0_TG/code2026/need_to_do/quiz/templates/quiz/frontend/test_paper_detail.html#L373-L435)

  3. **班级作业试卷** [do_class_assignment.html](file:///d:/0_TG/code2026/need_to_do/quiz/templates/quiz/frontend/do_class_assignment.html#L404-L405)（作业与考试共用同一答题页）
- **后端新视图**（AJAX POST）：`starcoin:use_hint_card`，入参 `question_id` + `source` + `ref_id` → 校验场景 → 生成提示 → 消耗 1 张 → 返回文本（含剩余张数）。

- **防泄题策略（关键）**：答案在服务端、前端只有选项，因此可安全实现。提示内容限定为：
  1. 题目有解析且**开头未点名答案** → 返回解析**前 40 字**；
  2. 无解析（或解析开头点名了答案）→ 返回「可排除一个错误选项」（单选/多选随机排除一个错误项，错误项 ≤1 时不给排除项）；
  3. 判断题 → 返回题干关键信息（不判对错）。
- **⚠️ 实施期加固（实测发现）**：原设计「有解析就返回解析前 40 字」会泄题——题库解析开头常直接写「因此B选项正确」「选项C错误」「故选D」，40 字内足以点出答案。现在改为：**片段中出现任一选项字母（或判断题出现「正确/错误」）即弃用解析策略**，退化为「排除一个错误选项」。抽样 600 道带解析的题：80% 仍可用解析提示，20% 退化，解析类提示中出现答案字母的为 0 条。

- ✅ **已决策**：提示内容「自动择一」（有解析给解析前 40 字，无解析给排除一个错误选项）；适用范围**公开试卷 + 错题组卷 + 班级作业试卷**。

### 10.1 每日登录赠礼（后台「🎁 登录赠礼」）

- 模型 [StarLoginGift](file:///d:/0_TG/code2026/need_to_do/starcoin/models.py#L469-L501)：一行 = 一件道具 + 免费档张数 + 会员档张数 + 启停 + 排序；`limit_choices_to` 限定**只能选「入背包」类道具**（改名卡 / 组卷卡 / 提示卡 / 头像框），即时生效型没有背包使用入口、人工核销型由管理员发放，都不适合自动赠礼。后台列表支持**行内直接改张数与启停**。
- 默认值（迁移 seed，与改造前硬编码一致）：破晓·辉月 免费 1 / 会员 2；回响之杖 免费 1 / 会员 2。
- 发放实现：`services.grant_login_gift(user)` 直接生成一条「已发放」的兑换记录（0 星币、不扣库存、不受限购），与兑换所得同源，背包余量 / 答题页张数 / `available_quantity` 共用一套口径；道具下架则跳过并记日志（避免发出去用不了）。
- **两条触发路径，均可安全重复调用**：
  1. **登录成功** → [hooks.on_login](file:///d:/0_TG/code2026/need_to_do/starcoin/hooks.py#L37-L56)；
  2. **当天首次访问任意页面** → [starcoin/middleware.py](file:///d:/0_TG/code2026/need_to_do/starcoin/middleware.py) 的 `DailyGiftMiddleware`：解决「登录后长期不退出登录（session 一直有效）当天拿不到赠礼」。
- **幂等**：以 [StarLoginStreak.last_gift_date](file:///d:/0_TG/code2026/need_to_do/starcoin/models.py#L304-L306) 为准，`select_for_update` + 事务防并发重复发放，**同一天只发一次**；session 标记 `star_daily_gift_checked` 做节流（当天已检查过就零查询）。
- 中间件只处理「已登录 + GET + 非 `/admin/` + 非 AJAX」，异常一律吞掉——福利发放绝不影响页面渲染。

### 10.2 错题组卷额度（后台「📐 组卷额度」）

- 模型 [StarWrongPaperConfig](file:///d:/0_TG/code2026/need_to_do/starcoin/models.py#L504-L531)（**单例**）：`free_daily_limit` = 免费用户每日免费组卷次数，默认 1，填 0 = 关闭免费额度。
- 规则（决策记录见 §8.1 #7）：

  | 身份 | 组卷次数 | 单次题量 |
  |------|----------|----------|
  | 会员 | **不限** | ≤ 10 题；用 1 张组卷卡当次**不限题量** |
  | 免费用户 | 每天 `free_daily_limit` 次 | ≤ 10 题；用 1 张组卷卡当次不限题量，且该次**不占**免费额度 |
  | 免费用户超额 | 每消耗 1 张卡组 1 次 | 同上 |

- 次数统计口径：**今日已用免费次数 = 今日生成的错题组卷试卷数 − 今日用掉的组卷卡张数**（被拦截/失败不会留下试卷，天然不计数）。
- ⚠️ **实现约束（务必遵守）**：**不要用 `created_at__date=今天`**——本库 MySQL 未安装时区表，`CONVERT_TZ` 会让查询**静默返回 0 条**（同一个刚创建的试卷：`__date` 查到 0 条、时间区间查到 1 条）。统一用本地自然日时间区间，见 [views_paper.py](file:///d:/0_TG/code2026/need_to_do/quiz/views_paper.py#L20-L30) 的 `_local_day_range()`。
- 前后台同口径：[create_wrong_question_paper](file:///d:/0_TG/code2026/need_to_do/quiz/views_paper.py#L962-L982) 服务端强校验，错题本页实时显示「会员不限组卷次数」/「今日免费组卷剩余 x/y 次 · 单次最多 10 题」。
- 迁移：`starcoin/0008_starwrongpaperconfig`（建表单例）。

### 10.3 前台道具展示对齐

- 错题本页额度条按**道具本名 + 图标**渲染（如 `📜「回响之杖」 ×N`），后台改名 / 改图标前台自动跟随；服务端提示文案同样取本名，不再出现「回响之杖（组卷卡）」这类功能名。
- 图标统一选用 **Unicode ≤ 9.0** 的表情：`🪄`(U+1FA84) / `🪙`(U+1FA99) 属 Unicode 13.0，旧字体缺字形会显示成方框，已分别改为 `📜` / `💰`。
